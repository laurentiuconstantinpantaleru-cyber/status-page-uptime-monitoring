Authentication

An organization admin creates API keys in the dashboard. A key is shown once, when it is created; store it somewhere safe. Send it in the Authorization header of every request.

Request header

Authorization: Bearer <public_id>.<secret>
What each key level can do
LevelCan
readList monitors and read their current status.
writeEverything read can, plus create, change and delete monitors.
  • A missing or wrong key gets 401 Unauthorized.
  • A read key that tries to change a monitor gets 403 Forbidden.

List monitors

GET/api/v1/monitors

Every monitor of the key's organization, with its current status: operational, degraded or outage.

Request

curl https://<your-status-host>/api/v1/monitors \
  -H "Authorization: Bearer <public_id>.<secret>"

Response · 200 OK

{
  "monitors": [
    {
      "id": 12,
      "name": "Hug The Mug",
      "url": "https://hugthemug.ro/",
      "interval_minutes": 5,
      "status": "operational"
    }
  ]
}

Read status

GET/api/v1/status/:org_slug

The same data as the public status page: the overall status, each component and the incidents still open. Times are UTC.

Request

curl https://<your-status-host>/api/v1/status/hug-the-mug \
  -H "Authorization: Bearer <public_id>.<secret>"

Response · 200 OK

{
  "organization": "Hug The Mug",
  "status": "operational",
  "updated_at": "2026-11-26T14:55:00Z",
  "components": [
    { "name": "Hug The Mug", "status": "operational" }
  ],
  "active_incidents": []
}

Rate limit

Each key can make 60 requests per minute. Request number 61 in the same minute gets 429 Too Many Requests; wait the seconds in Retry-After and try again.

Response · 429 Too Many Requests

HTTP/1.1 429 Too Many Requests
Retry-After: 30
Content-Type: application/json

{
  "error": "rate_limited",
  "message": "This key made more than 60 requests in the last minute. Try again in 30 seconds."
}
