Incidents

One failed check is not an incident: networks blip. An incident opens only when the failure is real.

  1. A worker's check fails.
  2. A second, independent worker checks the same URL straight away and must fail too.
  3. After 2 consecutive confirmed failures the monitor is Down and an incident opens, with its cause.
  4. After 2 consecutive successful checks the incident closes by itself.

When the worker is the problem

If most of one worker's monitors fail at once while the other worker reaches them fine, the fault is that worker's network (for example its DNS), not the sites. No incident is opened, and admins see a worker fault in the dashboard.

Updates

People on the team post updates as an incident moves through Investigating, Identified, Monitoring and Resolved. They appear on the status page.
